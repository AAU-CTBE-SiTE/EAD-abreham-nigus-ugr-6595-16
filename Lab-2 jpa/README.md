# jpa_lab

A small lab project that shows the basics of JPA (Jakarta Persistence) with Hibernate and MySQL. It maps a `Student` entity to a database table and runs create, read, update and delete (CRUD) operations on it through an `EntityManager`.

## Tech stack

| Component | Version |
|---|---|
| Java | 21 |
| Jakarta Persistence API | 3.1.0 |
| Hibernate ORM (JPA provider) | 6.4.4.Final |
| MySQL Connector/J | 8.3.0 |
| Lombok | 1.18.30 |
| Build tool | Maven |

## Project structure

```
jpa_lab/
├── pom.xml
└── src/main/
    ├── java/com/craft/
    │   ├── App.java        # EntityManagerFactory setup, CRUD methods, demo main()
    │   └── Student.java    # JPA entity (id, name, tech)
    └── resources/META-INF/
        └── persistence.xml # Persistence unit "studentPU" and DB connection settings
```

## The entity

`Student` is a JPA entity with three fields:

| Field | Type | Notes |
|---|---|---|
| `id` | `int` | Primary key, generated by the database (`GenerationType.IDENTITY`) |
| `name` | `String` | |
| `tech` | `String` | |

Lombok's `@Data` generates the getters, setters, `equals`, `hashCode` and `toString`.

## What `App` does

`App` creates one `EntityManagerFactory` for the `studentPU` persistence unit. Each operation opens its own `EntityManager`, and write operations run inside a transaction.

| Method | Operation |
|---|---|
| `createStudent(Student)` | `persist` a new student |
| `getStudentById(int)` | `find` a student by primary key |
| `updateStudentName(String, int)` | Change a student's name |
| `updateStudentNameAndTech(String, String, int)` | Change a student's name and tech |
| `deleteStudentById(int)` | `remove` a student if it exists |
| `containsDemo(int)` | Shows when `EntityManager.contains()` returns true or false |

Updates work through dirty checking: the method loads the entity with `find`, calls a setter, and Hibernate writes the change to the database when the transaction commits. No explicit `merge` or `update` call is needed.

`containsDemo` shows that `contains()` is true only for entities the current `EntityManager` manages:

- a new `Student()` that was never persisted → `false`
- a student returned by `find()` → `true`
- the same student after `detach()` → `false`

## Prerequisites

- JDK 21
- Maven 3.x (or an IDE with Maven support, such as IntelliJ IDEA)
- A MySQL server running on `localhost:3306`

## Database setup

1. Create the database:

   ```sql
   CREATE DATABASE jpadb1;
   ```

2. Check the connection settings in [persistence.xml](src/main/resources/META-INF/persistence.xml). By default the project connects as user `root` with password `root`. Change these to match your MySQL setup.

You don't need to create the table yourself. `hibernate.hbm2ddl.auto=update` creates or updates the `Student` table from the entity when the app starts.

> **Note:** `main()` first reads the student with id `1` (saved in an earlier part of the lab), and `containsDemo(1)` expects that row to exist. On an empty database, `getStudentById(1)` prints `null` and `containsDemo(1)` throws an exception when it calls `detach(null)`. Run the app once so it inserts rows, or insert a row with id 1 before you run it.

## Build and run

Build the project:

```bash
mvn compile
```

Run the demo from your IDE by running `com.craft.App`, or from the command line:

```bash
mvn compile exec:java -Dexec.mainClass=com.craft.App
```

Hibernate prints each SQL statement it runs (`hibernate.show_sql` and `hibernate.format_sql` are on), so the output shows the generated SQL alongside the demo's results.
